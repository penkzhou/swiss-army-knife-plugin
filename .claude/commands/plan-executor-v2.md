# Plan Executor

请参照 $ARGUMENTS 文档执行计划实施。使用 ultrathink 进行深度思考，遵循批量执行和检查点机制。

**在开始时宣布：** "我正在使用 Executing Plans 技能来执行这个计划。"

## 步骤 1：加载和审查计划

1. **读取计划文档**
   - 使用 Read 工具读取 $ARGUMENTS 文档
   - 使用 Explore subagent 阅读相关代码和文档获取上下文,确认当前文档是否准确，根据实际情况确认是否需要更新文档保证一致性

2. **批判性审查计划**
   使用 Explore subagent 完成以下工作：
   - 识别计划中的问题、疑问或关注点
   - 检查是否有缺失的依赖
   - 确认指令是否清晰明确
   - 评估计划的可行性

3. **决策分支**
   - **如有疑问：** 立即向用户提出，不要猜测或假设
   - **如需更新计划：** 先更新 $ARGUMENTS 文档，然后重新审查
   - **如无疑问：** 创建 TodoWrite 追踪所有任务，然后继续执行

## 步骤 2：批量执行任务

**默认批次大小：3 个任务/批**

对每个任务使用 general-purpose subagent执行以下步骤：

1. **标记为 in_progress**
   - 使用 TodoWrite 更新任务状态

2. **严格遵循 TDD 流程**
   - 🔴 RED: 先编写失败的测试
   - 🟢 GREEN: 编写最少代码使测试通过
   - 🔵 REFACTOR: 重构代码保持测试通过
   - 使用 Explore subagent 参考 `@docs/best-practices` 中的相关最佳实践

3. **执行计划步骤**
   - 精确遵循计划中的每个步骤（计划已提供细粒度步骤）
   - 运行计划中指定的所有验证步骤
   - 不要跳过任何验证

4. **标记为 completed**
   - 使用 TodoWrite 更新任务状态
   - 更新 $ARGUMENTS 文档中的计划进度状态

## 步骤 3：批次间报告

**每批完成后必须：**

1. **展示实施内容**
   - 说明完成了哪些任务
   - 展示关键代码变更

2. **展示验证输出**
   - 测试结果
   - 覆盖率报告
   - 其他验证输出

3. **等待反馈**
   - 说明："准备好接受反馈。"
   - **在收到用户反馈前不要继续下一批**

## 步骤 4：继续或停止

**基于反馈继续：**
- 如有需要，应用修改
- 执行下一批任务
- 重复步骤 2-4 直到完成

**立即停止并寻求帮助，当：**
- 批次执行中遇到阻塞（依赖缺失、测试失败、指令不清晰）
- 计划有严重缺陷导致无法开始
- 不理解某个指令
- 验证重复失败

**不要强行突破阻塞** - 停下来询问，而不是猜测。

## 步骤 5：完成开发

**所有任务完成并验证后：**

1. **宣布技能切换**
   - 说明："我正在使用 Finishing a Development Branch 技能来完成这项工作。"

2. **切换到完成技能**
   - 使用 `skills/collaboration/finishing-a-development-branch`
   - 遵循该技能验证测试、展示选项、执行用户选择

## 何时重访早期步骤

**返回审查阶段（步骤 1）当：**
- 用户基于你的反馈更新了计划
- 基本方法需要重新思考

**不要：**
- 强行突破阻塞
- 跳过验证步骤
- 猜测不清晰的指令
- 在批次间自行继续而不等待反馈

## 执行原则

1. **批判性思考** - 先审查计划，不要盲目执行
2. **精确遵循** - 严格按照计划步骤执行
3. **TDD 优先** - 所有代码改动必须通过 TDD 保证质量
4. **复用最佳实践** - 参考 `@docs/best-practices` 中的模式
5. **高效利用工具**
   - 合理使用 skills 提升执行效率
   - 合理使用 subagent 优化 context 使用
6. **验证不可省** - 不要跳过任何验证步骤
7. **遇阻即停** - 停下来询问，而不是猜测
8. **批次报告** - 批次之间仅报告并等待
